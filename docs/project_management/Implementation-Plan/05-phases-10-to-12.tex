\phase{10 --- Direct3D 12 and optional Vulkan providers}

\textbf{Objective.} Expand platform coverage only when there is a real target requirement and a testable implementation path.

\deliverables
\begin{itemize}
  \item Direct3D 12 provider for supported Windows configurations, including command queues/lists, resource states/barriers, fences, and lifetime rules.
  \item Vulkan provider only if cross-platform requirements justify it and the resource/synchronization implementation can be maintained.
  \item Operation adapters for the subset with demonstrated demand and conformance coverage.
  \item Platform-specific packaging, drivers/runtime checks, hardware CI, and diagnostic support.
\end{itemize}

\exitcriteria
\begin{itemize}
  \item Provider contract tests pass on real target systems.
  \item Resource state transitions and completion rules are covered by stress tests.
  \item A provider is not advertised as supported based solely on compilation; device-level tests are required.
  \item The cost of maintaining the provider is justified by an explicit supported-platform requirement.
\end{itemize}

\textbf{Decision gate.} Vulkan is optional, not a mandatory checkbox. Direct3D 12 is a Windows provider; it does not replace the cross-platform provider contract.

\phase{11 --- Model and inference integration}

\textbf{Objective.} Allow model inference to participate in image-processing workflows without turning \Project{} into a training framework or confusing a model runtime with a raw compute provider.

\deliverables
\begin{enumerate}
  \item A typed model operation boundary with explicit tensor input/output descriptors.
  \item Explicit image-to-tensor and tensor-to-domain-result conversions: layout, channel order, normalization, precision, color transformation, logits/probabilities/labels, and coordinate mapping.
  \item ONNX Runtime adapter as a higher-level model runtime; its internal execution providers remain owned by ONNX Runtime unless a supported interop interface exposes more detail.
  \item Optional Core ML adapter for Apple platforms, qualified against its actual model and device constraints.
  \item Optional PyTorch runtime adapter only if a deployment requirement justifies it; PyTorch training remains external to the core library.
\end{enumerate}

\exitcriteria
\begin{itemize}
  \item Model operations compose with image operations through typed conversions without hidden preprocessing.
  \item Inference outputs have explicit semantic result types and can be attached to images as typed layers where appropriate.
  \item Runtime/provider selection is not duplicated or contradicted between \IPR{} and the model runtime.
  \item CPU/GPU execution-provider choices and precision modes are observable and tested.
\end{itemize}

\phase{12 --- Planner optimization and production hardening}

\textbf{Objective.} Optimize demonstrated workloads and prepare the library for dependable consumption.

\deliverables
\begin{enumerate}
  \item Cost measurements for operation execution, allocation, conversion, transfer, synchronization, and full-pipeline latency.
  \item Segment-level routing that accounts for resource residency and transition costs; do not greedily select the fastest isolated kernel.
  \item Safe fusion/materialization optimizations only where semantic equivalence is proven by conformance tests.
  \item Resource caching and pooling with bounded memory, predictable eviction, and correct synchronization.
  \item Stable diagnostics and execution traces identifying operation/version and implementation, then recording the selected provider, device, conversions, synchronization, and fallback behavior.
  \item Package versioning, binary/source distribution, platform support matrix, API documentation, migration policy, examples, and release checklist.
\end{enumerate}

\exitcriteria
\begin{itemize}
  \item Benchmarks compare complete pipelines, not only isolated kernels.
  \item Routing improvements demonstrate end-to-end benefit and do not regress numerical conformance.
  \item Memory usage is bounded and resource release is verified under cancellation and failure.
  \item Supported platform/provider/operation combinations are documented from test evidence.
  \item A clean consumer project can install, build, run examples, and execute contract tests using documented command-line steps.
\end{itemize}
